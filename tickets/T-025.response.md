`game/view/hud/run_over.gd`; layout per fable-tickets.md section 2.4 (killer name in danger

LEVEL / PURSE / CHARGES, one `Retry` button, focused by default). Void deaths show `The Void`
/ `D-VOID` and no sprite; curse deaths show `curse: <id>` / `D-CURSE:<id>`.

anywhere (research/fable-tickets.md, the T-027 spawn-line row); unknown ids show
`TBD SHALL ARRIVE`, never a guess.

## sim/death.gd (killer + death codes) is ABSENT — read from the sim events instead

T-021's `game/sim/death.gd` is not on this branch and not on `main` (checked). The killer and
the death code are read from the controller's death event (`{"e":"death","code","killer"}`,
emitted by `_die`/`try_kill`) and the controller's `dead_code` / `dead_killer`. Killer-name
resolution order: normalised raw killer id against a roster table (e.g. `gift_larper` ->
`gift Larper (Tripmine)`); else the killer string verbatim; else the death-code map; else the
code itself. This is a temporary source swap: when T-021 merges, the same dictionary feeds
straight in. See DECISIONS D-T025-6.
