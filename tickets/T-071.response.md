## What was built

1. `game/sim/enemy_runtime.gd` — FloatBody and the T-071 system helpers, all generic (no
   content id anywhere in `sim/`):
   - `FloatBody`: per-floater kinematics read from the cfg (the future enemy.json; key names
     are a SPEC GAP, logged as D-T071-1 [CONTESTABLE]): `base_speed` (u/s),
     `pursuit_ceiling`, `burst_ceiling` (fractions of BASE run speed 9.0). Raw speed =
     base_speed x overtime (`speed_mul`) x `curse_speed_mul` (new runtime field the engine
     layer keeps from core stats: rate curses and repeatable +5% stacks); the clamp happens
     AFTER every multiplier, to ceiling x 9.0 (the SR-5 table's u/s column — fraction x base
     run, never fraction x the body's own speed; the toucher row is the proof: 0.75 x 6.75
     would give 5.06, the table states 6.75). `begin_burst(mult, ticks)` clamps duration to
     180 ticks (3.0 s) and per-tick speed to burst_ceiling x 9.0, so overtime cannot push a
     burst past 9.0 either. `step(row, api, dt, tx, tz)` moves through the existing
     never-multiplied SR-1 easing in `move_toward` (2.0 u/s vertical, both axes in sim ticks).
   - `tempo_mul` exposed to the behavior: raw/clamped from the pursuit path, clamped to
     [1.0, 1/0.6]; `api.tempo_ticks(base_ticks)` applies the 0.6-of-base floor at the
     conversion (D-T071-2).
   - `stack_phase(cycle, k, n) = cycle x k / n`; `_spawn_one` now derives `anim_t` and a new
     `phase_ticks` field from it (same values T-027 produced) (D-T071-3).
   - spawn separation >= 30 u between copies, in D-056 fallback order — T-027 had the rule;
     testing the cascade exposed a real bug: step (c) checked `min_sep` against the PLAYER
     instead of the already-placed copies, so a 2-copy plan without anchors could land both
     5 u apart. Fixed (a bug fix, no threshold touched; T-027's tests stay green) (D-T071-3).
   - `volley_plan` / `VolleyClock` (D-064 volley gap, generic): at most 3 balls per volley,
     9 ticks (0.15 s) between balls of a volley, volleys start-to-start exactly 45 ticks
     (0.75 s — one full jump) apart, remainder on the LAST volley (D-T071-4 [CONTESTABLE]).
   - `SalvoClock` (D-064 salvo life limit, generic): budget counted from the FIRST tracking
     tick, a restart after a broken lock never resets it, expires ON tick 360 — harmlessly
     (D-T071-5 [CONTESTABLE]).
   - `projectile_end` event {"cause": "solid"|"life"|"hit", position, tick} for dying
     projectiles (T-027 removed them silently) — "detonates on the pad" becomes observable
     and the view gets its explosion point; a launch pad's tiles are already slabs in the
     collision world, so no new blocking code was needed (D-T071-6 [CONTESTABLE]).
2. `game/tests/test_floaters.gd` (the SR-1/SR-3/SR-5 kinematics, generic configs carrying the
   SR-5 table's numbers — sim and tests name no content id):
   - overtime tier 8 + the +8%/stack speed curse x 3: the 6.75 u/s body (ceiling 0.75) moves

     120-tick cycle converts to exactly 72 ticks = 1.2 s; no-overflow case stays at tempo 1.0;
   - the 5.6 u/s body (ceiling 0.80) never exceeds 7.2 u/s over 180 ticks at overtime 8 +
     curse x3 + repeatable-stack x2 (raw 11.5), settles at exactly 7.2;
   - a Zoomies-style +60% burst: peak 8.96 <= 9.0, lasts exactly 180 ticks above the pursuit
     ceiling (a 300-tick request clamped), then falls back under 7.2; with the full overtime
     stack the burst clamps to exactly 9.0 and still ends after 180 ticks;
   - a 4 HU climb (2.0 u): closes in exactly 60 ticks = 1.0 s, identical with and without the
