  (no error text, nonzero exit; each seed replays clean alone, so it is accumulated
  state in the long-lived process, not a seed) — a failed chunk is reported and the
  batch continues, and the report honestly covers the logs that exist.
- Additive sim counter edits (the ticket's "T-080 adds two counters to level_clear"
  were absent on main): the controller's new `step_up` event (a walked ground rise of
  >= 1 HU with contact on both sides of the move) + run_log.gd counting `jump` /

  run_log.gd gained `dir_base` (default user://runs, unchanged behavior) so the batch
  parks logs in the repo's gitignored out/ (D-T081-2); bot_run.gd gained the
  `--log` / `--log-dir` CLI (D-T081-3). No movement number touched anywhere.
- `game/tests/test_run_report.gd` — synthesizes a 3-level run log through
  run_log.gd's own surface (the D-T080-9 no-bot-competence lesson) and asserts: the
  eight block headings print in order with terrain first, real fixture counts in
  blocks 1/3/5, and the honest fallbacks — the blocks whose records cannot carry
  their numbers print "not measurable from the current records: ..." instead of a
  number (blocks 2 and 6 entirely; block 7's walkway-width split).

  carries wall-clock time, and the loading screen + lobby walk consume no sim ticks

  beacon_enter -> level_start delta carries no lobby duration. The block prints the
  lobby counts split by offered bays (E / C / U / REST combinations as offered) and

  split IS printed, using the last gold gift's recorded chain (+0.05, cap x2.00)
  while the 240-tick window holds — chain_reset events write no record, so that is
  an approximation, stated in the source.
