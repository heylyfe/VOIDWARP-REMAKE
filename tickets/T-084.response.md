# T-084 - Animation player and telegraph sync

Delivered on this worktree's branch (t3/enemy-anim-telegraph-sync). Gate green; output at the
bottom. No ENEMIES.md sentence, FINAL decision or other ticket was contradicted, so PARKED.md
got no row and nothing was contested.

## What landed

- `game/view/enemy_anim.gd` (new): the per-enemy animation player. View-layer RefCounted; reads
  the parsed sprites.json (`anim` T-083 block + the T-016 `animations` list for
  body_rect/world_height) and is advanced ONLY by sim ticks:
  - `on_state_changed(state)` / `sim_tick()` / `attack_event(sim_tick)` - the frame is a pure
    function of (state, ticks_in_state): tick_ranges first (coil's flight 0-20/21-144/145-164),
    else ticks_in_state / ticks_per_frame with loop-wrap or one-shot hold. No view timer exists.
  - A state with no frames (kiwi's contact attack, the nuke's explosion, the larper's
    detonation) holds the last frame SHOWN; a finished looping state's wrap frame never becomes
    the held frame (it is computed on the switch tick, never displayed) - D-T084-1/D-T084-2.
  - `effect_params()` -> the shader uniform contract {flash, tint, scale_pulse, shake, alpha},
    computed from the same sim tick (common fade lerp, triangular scale pulse, 6-tick white
    flash, 0.7 dim, 0.05 u rumble shake). Effects never touch frames or body_rect - D-T084-4.
  - `hit_shape()` -> the hit cylinder from the body_rect of the frame SHOWN (height = body
    height, diameter = 0.8 x body width, per-frame world_height applied: coil flight 1.714 u ->
    landing 1.0 u). `probe_hits(px)` -> true only inside the body_rect AND alpha > 16, so
    transparent padding never hits (HITBOXES + TRANSPARENCY).
  - `contact_blocked()` -> true during the spawn fade (30 ticks; the block's own
    spawn_blocks_contact_ticks/duration_ticks when stated - address me's contestable 12) - D-T084-3.
- `game/tests/test_anim_sync.gd` (new, run_all contract: `run() -> Array[String]`): for each of
  the 12 enemies a scripted sim drives the player tick by tick and asserts:
  1. telegraph duration == DESIGN.md binding count (the test's own transcription: kiwi 12,
     coil 36, ben 75, isagi 72, nuke 150+90, YOU 90, larper none, toucher 18, seal 45,
     address me 300, Claude strings 36, gin 120) - both against the block's total_ticks and in
     the driven run length;
  2. the attack frame is the frame shown on the tick the attack event fires (event on the
     attack state's entry tick, isagi's volley also on local 9/18), 0 ticks of error;
  3. per-tick frame identity against the test's own re-derivation of the block, across the
     whole driven timeline (coil's flight and recover ranges are exercised end to end);
  4. the billboard normal faces the camera from 8 angles in every state (real billboard.gd
     instance, normal . forward <= -0.999 - the T-027 convention);
  5. a probe at (2,2) - transparent padding of the CURRENT frame - never hits, on every tick of
     every state; a probe on a body pixel of the frame does;
  6. spawn-fade contact blocking per D-T084-3;
  7. effect spot checks: kiwi pulse 1.0/1.12@t6/1.0@t12, ben flash full-white@t0 -> 0@t6, isagi
     recover tint 0.7, YOU rumble 0.05 u, toucher pulse 1.15@t9;
  8. the coil hitbox story: attack_flight t20 hit height 1.714 u -> attack_landing 1.0 u
     (the squashed coil has the squashed hitbox, from the real per-frame world_height data).
- DECISIONS.md: D-T084-1..D-T084-5 appended before `## Handover log`.
- TBD.md / PARKED.md: no rows - all 12 enemies are TBD placeholder art and their anim blocks
  (T-083) carry the real binding timings, which is exactly what this ticket plays; no asset
  blocked, no contradiction found.

## Notes for the next ticket (no action taken here)

- billboard.gd's `setup_from_sheet` does `float(doc.get("world_height", 1.0))`: safe with the
  top-level doc (scalar), but it would error if handed an `animations[]` entry whose
  world_height is per-frame (e.g. coil's cycle is a list). Whoever wires the player into the
  scene should pass the top-level doc.
- The effect parameters are produced per tick and pushed to the bound view via duck-typed
  `set_effect`; billboard.gd has no `set_effect` yet, so the shader material consume is the
  remaining integration step (D-T084-4 records the contract).
