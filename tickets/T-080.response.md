## The hard constraint

App/run_log.gd appends one JSON object per line to `user://runs/<run_seed>_<start_tick>.jsonl`.
It reads NO sim state: it consumes event dicts and app-layer calls only. The values a record
needs that no event carries are either derived from the event stream (the chain multiplier from
the gold-gift beat + chain_reset events + the 240-tick window arithmetic; pushed-in-120 from
push events; gold collected/available from the gift events; per-level timing from the log's
anchors) or handed in by the app layer, whose terrain dict / lobby ledger / purse are its own
inputs (level_start's slots/real_gifts/mines counts, run_start's seed and class, run_end's
level reached and purse). The replay comparison below is the proof nothing leaked.

## Where each record type is emitted

| type | emitted by | payload (verbatim owner fields) |
|---|---|---|
| run_start | app layer at log start | seed, class |
| level_start | app layer (bot_run._play_level) via log.level_started | slots, real gifts, mines, enemies in play (D-T080-5) |
| gift | EV_GIFT_COLLECTED (sim/gifts.gd) | slot id, black/gold, chain value (pre-increment, economy-parity) |
| void_fall | the controller's void_fall event, enriched sim-side (tile = the last grounded tile, nearest enemy body distance) | tile, nearest_enemy_dist, pushed_120, pushed_by (from push events, D-T080-3) |
| charge_spent | the same void_fall event | cause: "fall", free = before==after (D-T080-6) |
| charge_restored | EV_BEACON_ENTER (sim/beacon.gd), enriched with charges_before | before, after |
| mine_pass | the new typed `mine_pass` event (sim/mines.gd's 1.4 u bypass tracker: within 0.9+0.5 = 1.4 u of a live mine's centre, out again without contact; closest = the inside minimum) | slot id, closest horizontal distance |
| mine_contact | EV_MINE_CONTACT + the outcome event in the same tick's batch (defused / shielded / last_light / killed) | slot id, outcome |
| death | the controller's death dict, enriched: charges held, Last Light state (HUD lit/dim/grey), on_screen (D-T080-2) | killer id, death code, on_screen, charges, last_light |
| last_light | the controller's last_light_save dict | code, killer, charges |
| beacon_open | EV_BEACON_OPENED (the phase flips black -> gold) | (the tick is on the record) |
| beacon_enter | EV_BEACON_ENTER | tick, overtime_tier (from the overtime_tier events), gold collected / gold available |
| level_clear | EV_LEVEL_COMPLETE | black-phase ticks, gold-phase ticks, total |
| offer | app layer at lobby presentation (one row per unresolved bay) | bay, the three ids |
| pick | EV_ALTAR_SELECTED (the driver collects apply_select's event list) | bay, id, price (a negative price is the bounty) |
| lobby_enter | app layer (level just completed; pre-run = 0) | (phase "lobby") |
| lobby_exit | app layer, at the gate / before level_started | (phase "lobby") |
| run_end | app layer at the run's end (death, stuck, timeout or the harness stop) | level reached, purse |

Every record: `t` (run-wide accumulated sim tick, D-T080-1), `level`, `phase` (black/gold/lobby),
`type`, `payload`.
