# B7 - a gift or a tripmine on a tile the crumbling curse removed hangs in the air

**Verdict: DONE**

PARKED.md row 32. The `crumbling` curse removes 1-wide walkway tiles 1.2 s after they are
stepped on and returns them 5 s later, through the same `w["removed"]` set the platform
collapse uses. A gift or a tripmine standing on such a tile kept rendering in mid-air for
the whole 5 s. The B6 collapse sweep deliberately does not touch these slots, because the
curse's tiles RETURN and marking a gift `lost` would destroy it permanently for a
temporary hole.

PARKED.md row 32 is now fixed. The row itself is left for the orchestrator to close - this
ticket does not edit PARKED.md.

## What changed

- `game/sim/gifts.gd` - `slot_tile_key(i) -> String` delegates to
  `CollisionScript.tile_key(x, z, y_hu)` on the slot's own `x` / `z` / `y` (y in
  half-units, the same fields `slot_pos()` reads). The key format stays collision.gd's;
  nothing re-spells it. The sim never calls it - it exists for the view.
- `game/sim/mines.gd` - the same accessor for a mine slot id.
- `game/view/gifts_view.gd` - `set_removed(keys)` holds the world's live removed-tile set
  by reference (the `set_curses_state` / `set_viewpoint` idiom, so `sync()`'s signature is
  unchanged). `sync()` computes `gone = _removed.has(_gifts.slot_tile_key(i))` once per
  slot and folds it into both visibility lines: `_black[i].visible = shown and not gold
  and not gone`, `_gold[i].visible = shown and gold and not gone`. `setup()` clears the
  set. The Dull Gifts rim-glow block is untouched.
- `game/view/tripmine_view.gd` - `set_removed(keys)` and
  `root.visible = not _mines.is_consumed(slot) and not _removed.has(_mines.slot_tile_key(slot))`.
- `game/app/world.gd` - `_view_pass()` feeds `w["removed"]` to both views before they
  sync, so a hole that opens or closes is on screen the same tick.
- `game/tests/test_removed_tile_view.gd` (new) - the proof, four legs.
- `DECISIONS.md` - D-B7-1.

Nothing in the sim reads the new accessors, so `present()`, `remaining()`,
`straggler_ids()`, `all_black_collected()`, the pickup loop, `is_consumed()` and
`contact_at()` are exactly as they were. No state was added, so the state hash and the
replay checkpoints are unchanged.

## The test

`game/tests/test_removed_tile_view.gd`, discovered by `run_all.gd`. Every leg runs on a
real generated level through `world.build()` / `world.step()`, and the hole is opened
through the world's own tile applicator (`_apply_tile_events` with the curse's own
`tile_fell` / `tile_returned` events) - the exact call the crumbling dispatcher's events
reach. The curse's own 72 / 300 tick schedule is `test_curse_crumbling.gd`'s job.

- **gift leg** (level 1, seed 1): `slot_tile_key(i)` equals `collision.gd`'s own key for
  the slot; the gift renders visible; the tile falls -> the gift renders hidden, the
  control slot on an untouched tile still renders, `present(i)` is still true,
  `is_lost(i)` is false and `remaining()` has not moved; the tile returns -> the gift
  renders visible again; the tile falls again and one `world.step()` with the player on
  the slot collects the gift - it was collectible while hidden.
- **gold leg**: the same rule on the gold twin after the phase flip.
- **mine leg** (level 5, seed 0): the mine's root renders hidden over the hole, the mine
  is not consumed, `contact_at` still answers at its own point, and it comes back with
  the tile.
- **collapse leg**: `_collapse_sweep` loses the gift and drops the mine; both stay hidden
  with their tile in the removed set AND with it out of the set - the new term is a no-op
  on the collapse path, because `present()` / `is_consumed()` are what hide them there.

## RISKS

- **The hole is opened by injecting the curse's own event, not by driving the curse.** The
  test calls `world._apply_tile_events([{"e": "tile_fell", "key": ...}], 0)` - the exact
  call `world.step()` makes for the events `_curses.tick()` raises - rather than walking a
  player onto a 1-wide walkway edge and waiting 72 ticks. Driving the real curse would need
  a gift to happen to sit on an edge-lane tile, which the generator does not guarantee, so
  the injection is the honest way to pin the rule. The curse's own schedule and its
  step_on / edge-lane wiring stay `test_curse_crumbling.gd`'s coverage.
- **The rule is per-slot and reads the live dict by reference.** `set_removed()` stores the
  world's `w["removed"]` itself, not a copy, so a view that outlives its world would hold a
  stale dictionary. `world.teardown()` already frees both views, and `setup()` clears the
  set on a re-used node, so nothing in the shipped path can hit it.
- **Not fixed, found while working:** `game/view/gifts_view.gd`'s `sync()` calls
  `_gifts.slot_pos(i)` for the Dull Gifts rim-glow query on every slot every tick, and
  `slot_tile_key(i)` now adds a second per-slot dictionary lookup plus a string format on
  the same pass. Both are small, but the gift view's per-tick cost is now two string
  formats per real slot. If the view pass ever shows up in a frame budget measurement, the
  cheap fix is to cache the key per slot at `setup()` time (the slot's tile never moves) -
  deliberately not done here, because it would put a second copy of the key in the view and
  the ticket's rule is "the view computes no geometry".
- **Not fixed, found while working:** `PARKED.md` row 9 (the sim never expires telegraph
  footprints) is still open and still blocks `address_me`'s gate; it is unrelated to this
  ticket and was left alone.
