## Decisions of this ticket

- **D-T013-1** — schema dialect + file naming (above); per-kind schemas for the four seated
  kinds, six data schemas, parse-only scan for gimmicks/modes.
- **D-T013-2** — vocabulary pinning. ACCEPTS D-T014a-1's open points as written: `severity` is
  the lowercase word (mild/harsh/brutal) — the schema enum mandates it, the bounty lookup uses
  it; `requires_enemy` is pinned to the 12 fixed enemy ids with `"you"` for YOU?! — now
  non-contestable, not a per-file assumption (the enemy folders land with Wave 3 and must use
  these ids). `tier` ∈ T1..T5, class vocabulary = dasher|glider|athletic (incl. `class:` prefixes
  on `when`). stat/hook enums in the two content schemas must byte-equal `core/stats.gd` /
  `core/hooks.gd` (asserted by test_content.gd) — updating them is one commit, two files.
- **D-T013-3** — boot-refusal contract: `registry.load_all()` refuses = pushes one error per
  offending file (name included) and returns `ok=false`; the app boot (T-024) must quit(1).
  `content_ids()` is `"curse:"/"enemy:"/"upgrade:"/"biome:" + id` (singular).
- **D-T013-4** — shop pool semantics: a drop-in upgrade is registerable with zero edits outside
  `content/` but is NOT SOLD until `data/upgrade_pools.json` lists it — a data edit, never a
  core edit (§8's pool file IS the shop catalog). Asserted pre-emptively in test_dropin.gd.
